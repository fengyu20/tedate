# Decisions that persist

Read when a recommendation or hand-off could touch an earlier choice (Run step 3).

The **baseline** is what a new change starts from: the accepted decisions, the existing pages and any written conventions.

- An **accepted** decision stays in force until a stated reason meets its reopen condition: new evidence, a failed premise, a changed audience. A newer tool, a competitor's feature or the agent's own preference leaves it in force. The owner can replace an accepted decision at any time; record the change and the reason.
- An installed skill's way of working is observed until the owner adopts it; once adopted, it is an accepted decision like any other. A tool's actual limits are facts, which no decision changes. When installed skills' rules conflict, start from the accepted decisions. Where none covers the conflict, recommend one rule, a split by part of the work, or neither, with a reason from the product; the choice is the owner's. Draft a record entry (decision, reason, reopen condition) only when the choice should hold across sessions.
- A style or rule that merely exists in the product is **observed**. Report it as observed; it becomes accepted when the owner confirms.
- Rules extracted from live pages are the **current implementation** or **candidate rules**. Label one an invariant or an accepted exception only when an accepted decision records it or the owner confirms it.
- A project that spans several sessions keeps a one-page record by default: for each accepted decision, the decision, the reason and the condition that reopens it. A one-off task needs none. Write files only with the owner's authorisation; in advise mode write nothing and state the baseline in the reply instead.

## Decisions to write before the second page

Leads from one project, where each was settled only after rework. Each applies when its condition holds:

- When a status is derived from several facts, it has one definition that every page reuses.
- When a page states facts from outside sources, each carries its source and date; the wording is the product's own, apart from names and terms quoted as such.
- When content has dates, a one-off date carries its year and a temporary notice its expiry condition.
- When a product will have several pages, shared header, layout and visual conventions exist before the second page.

If the project has an AGENTS.md (or equivalent) and the owner agrees, point it at the record.
